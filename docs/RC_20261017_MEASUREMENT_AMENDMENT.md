# 全窗口测量修订（在v2观测前冻结）

记录时间：2026-10-17 11:35:24 UTC。功能源码冻结`3647ded`，main清单`998b3fc31ae9fd813f5f916a345240451d476283a9b05672b1bcc6c80cf89504`，JAR`1ae895792a44ca791a8ae1b6516ab35014f4c7e769e4aaccc016aa9adb2d074f`。此修订不修改功能、SQL/WAL协议、配置限额或已冻结的旧目标。实际探针构建/观测时间在各manifest另记。

原测试探针v1保留全部数据。其Runtime.tick p99只是单方法分位，Ports/编解码调用有各自完整窗口直方图，但无法从这些聚合数据逆推每tick去重累计模组耗时。因此先前Runtime方法成本观测不能作为“全部模组每tick p99”通过证明。

v2增加同一完整tickServer frame内、同一线程的已插桩模组最外层scope累计；嵌套只算一次，无调用tick记零。tick外的主线程调用独立报告，不强行分配到相邻tick；worker不计入主线程。增加overflow/invalid样本计数，出现无法确认的完整性问题，该指标不合格。直接保存回调和可选兼容入口按实际插桩manifest报告覆盖；GUI或其他未插桩入口不冒充全CPU成本。仍报告完整tickServer墙钟耗时、实际tick起始间隔/TPS、生成器成本。插桩开销是测试条件，不宣称为零。

用相同v2探针、原固定输入、40次低流量探测、30秒预热/120秒稳态，重新运行f3快速模式三布局，再运行3647ded候选三布局。两版都保存固定窗口及真实排空总成本。v1原始结果和错误候选不覆盖；不得跨探针版本把差值当成纯功能收益。

为防止新探针使基线变慢后放宽验收：旧v1冻结的FE相对延迟数值门仍保留（同服307.852ms，跨服411.995ms，混合512.571ms），并同时检查v2同条件基线派生的原公式门，取较严者。固定/完整SQL事务与语句20%门也同时检查旧v1已记录阈值和v2同量输入阈值；新基线不能将旧目标失败改成成功。主线程绝对门仍为原2ms/1000端点3ms，只有实际覆盖的完整窗口指标能评定，未测的规模/入口单列。旧“三路径事务均下降30%”失败也不改写。

本修订的目的和代价：补齐主线程累计测量，增加约12分钟同条件基线实测，降低缺少覆盖的错误通过风险；不降低门槛或追求事后选择最好结果。
